# 提供商配置 UI 改进设计

## 概述

基于 v0.4.0 实现的提供商配置功能，收集用户反馈后提出的 UI 改进方案。

## 改进内容

### 1. 提供商右键菜单增加"复制"选项

**现状：** 提供商条目只提供右键删除选项。

**改进：** 右键菜单增加"复制提供商"选项，复制后：
- 名称自动添加" 副本"后缀
- API Provider 和 Base URL 相同
- API Key 相同（共享同一个 keychain key）
- 新提供商创建后，可独立修改

### 2. UI 布局重构：层级嵌套

**现状：**
- 左侧列表分为"提供商"和"模型映射"两个同级 Section
- 选中映射后在右侧详情页编辑

**改进：**
- 左侧只显示"提供商"列表
- 选中提供商后，右侧详情页内显示该提供商的所有模型映射
- 模型映射以卡片形式展示，每个卡片包含：
  - Switch toggle（启用/禁用）
  - 映射名称、模型名称
  - 点击展开/收起完整编辑表单

**布局示意：**

### 3. 拖动排序

**现状：** 配置条目按添加顺序排列，无法调整。

**改进：**
- 提供商列表支持拖动排序
- 每个提供商内的模型映射支持拖动排序
- 排序结果持久化保存

**实现方式：**
- 使用 SwiftUI 的 `.onMove` modifier
- ConfigManager 新增 `moveProvider(from:to:)` 和 `moveMapping(providerId:from:to:)` 方法
- 排序顺序存储在 UserDefaults

### 4. 模型映射卡片内联编辑

**展开状态包含：**
- 客户端模型名（TextField）
- 实际模型名（TextField）
- 参数注入区域（Temperature, Max Tokens, Top P, 等）
- 思考模式覆盖设置
- 自定义参数字段
- 保存/收起按钮

**交互：**
- 点击卡片标题栏 → 展开/收起
- 展开时显示完整编辑表单
- 修改后需点击"保存"
- 点击"收起"时如有未保存更改，提示保存确认

## 数据模型变更

### ProviderConfig 排序

方案 A：使用数组顺序（推荐）
- providers 数组本身的顺序即为显示顺序
- 移动时交换数组元素位置
- 无需额外字段

方案 B：新增 order 字段
- 每个 ProviderConfig 有 `order: Int` 字段
- 加载时按 order 排序
- 移动时更新相关 order 值

推荐方案 A，更简洁。

### ModelMapping 排序

同样使用数组顺序方案：
- mappings 数组按 providerConfigId 分组后的顺序为显示顺序
- 每个 provider 组内可独立排序
- 移动时更新 mappings 数组顺序

## 实现优先级

1. **P0 - 核心布局重构**：左侧只显示提供商，右侧内嵌映射列表
2. **P0 - 映射卡片组件**：可展开收起的编辑表单
3. **P1 - Switch toggle**：映射条目启用/禁用开关
4. **P1 - 拖动排序**：提供商和映射排序
5. **P2 - 复制提供商**：右键菜单选项

## 兼容性考虑

- 现有数据无需迁移（数组顺序即为默认顺序）
- 删除顶层模型映射 Section 后，用户需通过提供商进入映射配置
- 如有"孤儿映射"（providerConfigId 无效），可在提供商详情页底部显示"未分类映射"区域
